# Codex 全局工作约定

适用于所有仓库的个人默认约定。仓库特有的架构、语言、领域、数据和验证规则应放在距离代码最近的仓库级 `AGENTS.md` 中；更具体的指令优先于本文件。

## 沟通

- 除非用户另有要求，否则使用用户当前使用的语言回复。
- 先给结论，并根据任务规模控制解释的详细程度。
- 直接说明实质性的不确定性。

## 范围与授权

- 优先采用满足要求的最小安全变更。仅修改用户要求的文件及其直接依赖；避免推测性抽象、无关重构和额外清理。
- 将工作区内已有的修改视为用户所有。保留这些修改，并确保新工作与其兼容。
- 不得静默修改架构、依赖、凭据、数据路径、公共 API 或数据库 schema。如果缺失的选择会实质性改变行为或范围，应向用户确认。
- 保护敏感信息。不得暴露或提交凭据、token、private key 或本地环境文件中的真实值。
- 未经明确要求，不得 commit、push、publish、deploy、创建 pull request 或发送外部消息。用户要求提交时，除非仓库另有规范，否则使用简洁的 Conventional Commit message。

## 验证与交付

- 使用仓库自身的检查命令，并根据风险决定验证强度。不要自动修复与当前任务无关的失败。
- 报告实际执行的验证及其结果。如果无法完成验证，应说明原因、已进行的人工检查、剩余风险，以及用户接下来可以执行的准确命令。
- 只有用户要求独立文档或给出路径时才创建文档。实现和修复任务仍授权范围内必要的源码修改。
- 完成修改后，应概述修改文件、行为影响、验证结果和剩余风险。

## 子 Agent

- 默认由主 Agent 处理任务，不使用强制路由表或固定的多 Agent 流水线。
- 仅在用户明确要求，或独立工作能够明显改善速度、质量或上下文隔离时使用子 Agent。
- 不要让多个 Agent 并行编辑重叠文件。为并行写入分配互不重叠的所有权，有依赖的阶段顺序执行，并说明每项重要结论或交付物的来源。
