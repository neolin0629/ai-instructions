# 量化约定

只将相关约定应用于受影响的行为。根据用户请求、供应商文档和现有代码确定实际约定；仅修改命名或文档不要求审计整条数据流水线。

## 数据与执行约定

- 在影响正确性时，明确品种范围、数据频率、时间区间，以及历史回测、模拟盘或实盘模式。
- 历史信号只能使用当时已可获得的数据。区分事件发生时间和数据可用时间，明确 lag，并区分信号生成时间与执行时间。
- 说明价格复权口径，区分信号价格与可成交价格。时间区和品种代码采用一致约定；在受影响时明确排序、重复值、缺失值、NaN 和 Inf 的处理。
- 回测必须说明适用的手续费、滑点、资金约束、保证金和强平假设。缺失输入标为假设或证据缺口，不编造因子公式、供应商字段或 API。
- 上线按历史回测 → 模拟盘 → 小资金实盘安排。只执行已授权的阶段；编写交易代码不代表获准实盘下单。

## 存储偏好

以下是新存储决策的个人默认偏好，不是迁移要求。除非修改技术栈在任务范围内，否则沿用现有方案；只引入当前负载需要的组件。

| 用途 | 默认选择 |
|---|---|
| 需要事务的业务记录：订单、账户、配置、元数据 | PostgreSQL |
| 大规模、追加为主的历史 K 线或 tick 分析 | ClickHouse |
| 本地分析及 Parquet 上的 SQL 查询 | DuckDB |
| 临时实时层：消息、缓存、共享状态、锁、限流 | Redis |

- 权威业务记录和历史数据保存在持久化存储中，Redis 不能成为它们唯一的事实来源。
- 超过 10 万行的本地缓存优先使用 zstd 或 snappy 压缩的 Parquet；用户或集成接口要求 CSV 时除外。

## 验证

根据变更涉及的约定选择检查。历史信号变更可对比截断至时间 t 与包含后续输入时，t 及之前的信号是否一致；时间戳检查验证选定的时间区策略；回测结果列明使用的成本假设。复用已有证据，相关检查通过后停止，不要求每个任务都执行全部检查。仅要求设计时，描述所需检查，不执行回测或交易阶段。
