# 全局工作约定

子仓库特有的架构、领域、表结构、验证命令写在该仓库自己的 `CLAUDE.md` / `AGENTS.md` 里，更具体的指令优先于本文件。

## 语言

- 使用用户使用的语言回复。
- 注释、commit message、文档正文：中文。例外：已有英文约定的仓库（开源项目、对外协作）沿用其约定。
- 标识符、函数名、类名、日志消息、配置键、表名、字段名、文件名：英文（为了可 grep）。

## 改动边界

- 不静默变更架构、依赖、凭证、数据路径、公开 API、表结构 —— 这几类必须先说；部署、发布、开 PR、发外部消息则要等到被要求才做。
- 绝不输出或提交真实凭证、token、私钥，以及本地环境文件里的真实值。
- 工作区里未提交的改动归用户所有，必须保留 —— 不要为了让自己的改动干净落地而回退、stash 或覆盖它们。
- 只被要求审查、诊断、解释、汇报时保持只读，除非同时也要求了改动。
- 需要 commit 时用简洁的 Conventional Commit 格式，除非仓库另有约定。

## 新项目默认（Python 项目）

- Python 3.10+，`from __future__ import annotations` 作为第一条语句 —— 有模块 docstring 时排在它之后；依赖用 `uv` 管理，不用 pip。
- 数据处理优先 Polars / DuckDB；pandas 留给小数据和兼容场景。
- 需要后端服务时用 FastAPI。

## 存储分层（按用途选，不混用）

| 用途 | 选型 |
|---|---|
| 业务主库：配置、订单、账户、元数据，需要事务和关系 | PostgreSQL |
| 海量历史时序：K 线、tick，只追加、读多写少的分析查询 | ClickHouse |
| 单机分析、读 Parquet、中等数据量快速 SQL | DuckDB |
| 实时层：消息分发、tick 缓存、跨进程状态、分布式锁、限流 | Redis |

- Redis 永不作为最终存储，关键数据必须周期性落 PG / CH；历史数据和关系数据都不进 Redis。
- 超过 10 万行不用 CSV，除非明确要求；本地缓存用 Parquet（zstd / snappy）。

## 量化正确性护栏（涉及行情、因子、回测、实盘时适用）

- **禁止 look-ahead bias**：历史回测不得使用当时不可得的数据。用 lag / shift 时说明滞后期，并区分信号生成时间戳与执行时间戳。
- **复权与价格基准**：明确复权方式，区分信号计算用价与成交执行用价。
- **时区**：datetime 全部 timezone-aware 或全部 naive，不混用。
- **回测真实性**：必须计入滑点、手续费、资金约束、保证金与爆仓风险，不假设无限资金零成本。
- **上线顺序**：历史回测 → 模拟盘 → 小资金实盘，不跳级。
- **不编造量化逻辑**：因子公式、复权规则、数据字段、行情商 API 一律不臆造，不确定就要文档。

## Subagent

- 不要并行编辑重叠文件。有依赖关系的阶段顺序执行，并说明哪个结论出自哪个 agent。

## 产出物

- 只在用户要求独立文档或给了路径时才写文档文件，否则在对话里返回结果。这条管的是书面产出，不管源码：实现和修复任务本身就授权了范围内必要的文件改动。
- 验证没跑成、或用户需要自己复现时，给可复制的验证命令，用仓库自己的命令。完全无法验证时说清为什么、手动检查了什么、剩余风险是什么。

## Bootstrap

新项目要落地 Python 编码规范时，从 `~/.claude/templates/code-dev.md` 取种子，复制进该项目的 `CLAUDE.md` 后按实际情况改写，不要凭记忆重写。
