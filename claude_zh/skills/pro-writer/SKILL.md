# 专业写作

核心不是「去 AI 味」，而是**说出值得说的话**：先想清楚要说什么，再想怎么说。

## 适用范围

用于读者要据此理解、决策或执行的文档：报告、分析、白皮书、方案、综述、长篇技术文章。日常写作（回复、消息、注释、README、笔记、短文案）不需要本技能，直接写即可。

## 动笔前

用这五个问题指导写作，优先从用户请求和已有材料中确定答案。只有缺失答案会实质性改变选题、受众、核心论断或验收标准时才询问；否则说明低风险假设后继续。不得编造事实来填补缺口。

1. 这篇文章的核心一句话是什么？（一句话说不出来 = 还没想清楚）
2. 读者只记住一件事，那件事是什么？（让它突出，其余让路）
3. 读者是谁，他已经知道什么？（决定深度、术语量、什么可以跳过）
4. 哪部分我自己还没想透？（那部分保持诚实，别用自信的填充物糊过去）
5. 这需要什么体裁和长度？（体裁决定结构和节奏）

如果题目本身没有值得说的东西，**回到选题**，编辑技巧救不了空文章。

## 质量线

**内容**

- 说具体的、诚实的、自己相信的话，用仍然精确的最简方式说
- 结论先行：报告和方案开篇先给答案，再给支撑
- 区分数据、推断和观点，让读者分得清哪句是哪类
- 范围、假设和局限影响结论使用方式时，明确写出
- 不注水。删掉「99% 包装 1% 内容」的部分。一句话删掉不损失意义，就删掉
- 没有把握的地方如实标注，不假装确定

**规避 AI 腔**

- 模板化开头（钩子 + 痛点 + 承诺）和暖心祝福式结尾（「你值得……」）
- 缓和词与强调词滥用：「本质上」「其实」「归根结底」「essentially」「ultimately」
- 连接词密度过高（「因此」「此外」「moreover」一句接一句地堆）
- 翻译腔词汇和生硬直译
- 「不是 X，而是 Y」当成口头禅反复出现
- 排比句全部切成一样长、一样节奏
- 每段都以一句金句收尾
- 替读者说一句话，只为了纠正它

**准确**

- 不编造数据、来源、人物、事件、引语
- 论断追溯到出处（用户笔记、参考资料、论文、数据集），标明来源
- 学术或专业结论先查一手资料
- 数字、日期、姓名、归属必须可核验；术语和单位全文保持一致

## 交付前自查

做一次完整通读：开头是否模板化 → 结尾是否祝福化 → 缓和词密度 → 连接词密度 → 翻译腔 → 「不是 X 而是 Y」频率 → 排比句是否过于齐整 → 事实核查 → 中文排版（中西文混排间距、标点、引号、数学符号）。中文内容在已安装时用 `gr-content-ai-avoid` 和 `gr-chinese-typography-rules` skill 完成这一步。

交付前修正自查发现的问题。仅在用户要求，或尚未解决的问题影响准确性或使用时，说明自查详情；否则直接交付成稿。

## 行为

- 尊重用户指定的结构、语气、长度
- 匹配读者的知识水平：解释他不知道的，跳过他知道的
- 按用户要求完成相应篇数。批量任务连续推进，无需逐篇确认；用户要求分阶段审阅，或遇到需要其决定的重要问题时除外
- 只在用户要求独立文档或给出路径时创建文件；已有文档的改写请求允许范围内的编辑。其余情况在对话中返回成稿
